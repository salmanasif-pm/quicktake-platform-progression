## Description

### **Problem Statement:**

DISH currently lacks a real-time system to track the movement and location of physical assets (approx. 75,000+ items) across various facilities. This leads to:

- Inaccurate geolocation data in financial systems.
- Incorrect property tax filings and audits.
- Delayed asset visibility (data may be 1–6 months old).
- Heavy reliance on manual audits and site visits.
- No RFID, barcode scanning, or centralized visibility.
- Existing systems like ServiceNow are only used by IT, covering ~20% of assets.

## **Goals / Outcomes:**

- Enable **real-time asset location tracking** across data centers.
- Eliminate dependency on manual updates and site visits.
- Reduce incorrect property tax payments by ensuring accurate asset location.
- Improve internal transparency and reporting for asset usage and movement.
- Provide scalable architecture that can eventually expand to 200+ facilities.

## **Business Requirements:**

1. **Track Real-Time Location of Assets:**
   - Capture asset transfers between locations (e.g., from Bluffdale, UT to Gilbert, AZ).
   - Show rack-level asset visibility in data centers (Cheyenne & Gilbert to start).
2. **Minimize Manual Data Entry:**
   - Remove need for spreadsheets or emailed updates.
   - Automatically log movement data when assets are physically moved.
3. **Flexible & Scalable:**
   - Must support 30,000 assets initially (in 2 facilities).
   - Scalable to all 75,000+ assets and ~215 nationwide locations.
4. **Cost Efficiency Justification:**
   - Support a business case: system cost (~$200K) vs. projected tax savings & reduced labor.
   - Ability to generate usage reports for ROI tracking.
5. **Internal Presentation Package:**
   - Proposal deck, architecture diagram, business case (TCO/ROI), and timeline for VP approval.

## **Technical Requirements:**

### Phase 1: System Setup for Cheyenne, WY and Gilbert, AZ

1. **Asset Registry Integration:**
   - Use existing **serial number** tracking (not asset tags).
   - Optional: support for future RFID/barcode integration.
2. **Real-Time Geomapping:**
   - Assign geolocation (and rack position) to each asset.
   - Automatically update when assets are moved.
   - No manual triggers (e.g., email updates) required.
3. **Data Center Rack Mapping:**
   - Visual interface showing rack layouts and asset positions.
   - Flag when assets go offline or are physically removed.
4. **Integration with ServiceNow (Optional, IT Only):**
   - If feasible, pull or sync IT asset data with ServiceNow.
   - Non-IT gear (80%) to be managed via new system.
5. **Backend Architecture:**
   - Central database to track all assets.
   - Asset schema: `Serial No, Location, Rack ID, Asset Type, Status, Timestamp`
   - System logs for movement history.
6. **Access Control & Permissions:**
   - Role-based access (Admins, Viewers, Engineers).
   - Support for audit trail/reporting.
7. **Offline to Online Sync (Optional):**
   - In case of offline tracking, system should sync changes once online.
8. **User Dashboard:**
   - Search by asset, serial, location.
   - Reports on moved assets, location mismatches, and audit readiness.

## **Additional Notes:**

- **Standardization varies**: Equipment types differ across racks and locations.
- **RFID Tagging**: May be added if there is a need and we need to suggest this as well if this is required or not.
- **Data entry bottlenecks**: Need to reduce reliance on manual logging and engineers.
- **Deployment Model**: Cloud-based or on-prem (to be finalized based on DISH preference).
- **Timeline Sensitivity**: No hard deadline, but faster delivery = faster executive buy-in.
