## Description

## **1. Problem Statement**

The goal of this MVP is to **create a lightweight, invite-only networking application** that enables **mutual (two-way) connections** between users. Each user can control **what specific fields of information** are visible to their connections and can update or revoke access in real-time.

This MVP is a **functional prototype**, designed primarily to **validate the concept** and **test usability** within a small, invite-only community.

---

## **2. Objectives**

- Build a **mobile-first application (iOS & Android)** to allow users to connect, share, and control visibility of personal information.
- Create a **two-way connection model** (“Handshake”) where both users agree to connect.
- Allow users to **define and manage information visibility** at different permission levels.
- Keep the MVP **light, simple, and secure**, without complex business or monetization layers.
- Lay the foundation for future iterations (V2, V3, etc.) that may expand scope.

---

## **3. Functional Requirements**

### **3.1 User Management**

- **User Registration & Authentication:**
  - Users sign up using their **phone number** (primary method).
  - Optional: Email-based registration may be added later.
  - Phone and email must be **verified** (via OTP or confirmation code).
  - Upon profile update, users may need **re-verification** to confirm authenticity.
- **Login Methods:**
  - Login via verified phone number (preferred).
  - Optional: Email login (not mandatory for MVP).
  - No social login integration at this stage.

---

### **3.2 Profile Management**

- Each user maintains a **personal profile** with editable information fields.
- When a user updates their profile, **connected users automatically receive the updated info** in real-time.
- Information fields include (for MVP, exact list TBD but discussed as limited/basic):
  - Name
  - Phone number
  - Email
  - (and other simple contact fields as needed)
- Users can **define visibility groups** (e.g., Basic, Friendly, Best Friend) to control which fields are shared.
- Users can **increase or decrease visibility** for existing connections at any time.
- The system must ensure **real-time synchronization** when profile visibility is changed.

---

### **3.3 Connections (“Handshake”)**

- A **two-way connection model** — both parties must mutually agree to connect.
- Users can:
  - Send and accept connection requests.
  - View their list of current connections.
  - Remove connections or reduce visibility levels.
- Each connection level determines how much information is visible (e.g., name only vs. full details).
- No administrator oversees or monitors connections — the system is **fully user-driven**.

---

### **3.4 Invites**

- **Invite-only mechanism** for MVP testing.
- Users can invite others via code or link.
- No defined limit on invites at this stage (can be open or restricted later).
- Invite flow similar to other social apps (e.g., Instagram/LinkedIn style connection).

---

### **3.5 Core Actions Available to Users**

- Create an account.
- Edit and update profile.
- Send or accept invitations (“Handshake”).
- Adjust information visibility with each connection.
- View and manage list of connections.
- Remove or downgrade connection visibility.

---

### **3.6 NFC / Touch Integration (Optional for MVP)**

- NFC-based quick connection (“tap to connect”) feature discussed as a **future enhancement**, not a core MVP requirement.
- The handshake concept should be designed to allow NFC integration later.

---

### **3.7 Platform Scope**

- MVP will be a **hybrid mobile application** for **Android and iOS**.
- Users should be able to **download from App Store / Play Store**.
- **Web version is not required** for MVP but may be introduced later if an admin or reporting portal is added.
