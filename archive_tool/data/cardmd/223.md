## Description

### **Problem Statement** (Salman was with me on the call as well)

Modern organizations often rely on multiple cybersecurity and database solutions—each with its own dashboard, data sources, and alerting mechanisms. This creates **fragmented visibility**, increases **operational overhead**, and leaves **security gaps** due to lack of integration across platforms.

**Diverge** aims to solve this by developing a **unified, scalable dashboard** that provides a consolidated view of cybersecurity and database security insights. The goal is to offer clients a **simplified, real-time security overview**, regardless of the tools they use, helping them make better decisions and respond faster to threats.

### **Technical Requirements for the Dashboard Solution**

#### **1. Core Features**

- **Unified Dashboard Interface**: Web-based UI showing high-level metrics, alerts, and drill-down views.
- **Real-Time Data Sync**: Ingest and display real-time or near-real-time data from multiple platforms.
- **Role-Based Access Control (RBAC)**: Admins can manage permissions based on user roles (e.g., read-only, admin).
- **Multi-Tenant Support**: Ability to onboard and manage multiple clients from the same platform.

#### **2. Integration & API Support**

- **API Connectors** for popular tools (initial targets may include):
  - **Oracle Cloud Guard**
  - **AWS Security Hub / CloudWatch / RDS logs**
  - **Microsoft Azure Security Center**
  - **Splunk**
  - **SIEM solutions** (optional, depending on client stack)
- **Data Types to Ingest**:
  - User activity logs
  - Role/privilege assignments
  - Security alerts (e.g., DDoS, unauthorized access, privilege escalation)
  - Database queries and export activity
- **API Architecture**:
  - RESTful APIs for external system communication
  - Webhooks for event-driven updates
  - Support for JSON data formats

#### **3. Security Monitoring Capabilities**

- **Custom Alerts**: Triggered by conditions like:
  - Unusual login locations/IPs
  - Role escalation (e.g., read-only user gaining DBA rights)
  - Sudden mass exports or deletions from sensitive tables
- **Audit Logs**: Track all system activity within the dashboard
- **Anomaly Detection (Phase 2/Optional)**: Basic ML-based anomaly scoring

#### **4. Deployment Options**

- **Cloud-Native Architecture** (preferably):
  - AWS or Azure
  - Docker + Kubernetes for scalability (optional)
  - Database: PostgreSQL or MongoDB
- **Self-Hosted Option** for clients with strict compliance needs (optional) - This is down the lane and can be looked into if needed.
