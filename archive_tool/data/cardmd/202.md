## Description

# Problem Statement

Minerva Medical Group requires a **secure, cloud-based health risk assessment system** that accepts health-related survey responses containing personal health information (PHI), runs those responses through a defined algorithm, and produces environmental hazard **risk scores**. The system must support multiple client sites, provide role-based access and auditability, be maintainable and scalable, and be hosted on Azure with HIPAA compliance considerations. Luke will provide the algorithm structure and other detailed inputs needed to implement scoring and outputs.

---

# Requirements (strictly as discussed)

## 1. Functional Requirements — Survey & Data

- Support creation and intake of health-related **survey responses** (the number of questions and exact content to be provided by Luke).
- Store survey responses tied to individual users/logins.
- Allow survey responses to be processed by the algorithm supplied by the client to generate a **risk score**.
- Allow users to query the system with different environmental conditions to receive corresponding risk scores based on the stored survey response.

## 2. Algorithm & Outputs

- Implement the algorithm structure and scoring logic that Luke will provide (algorithm structure, number of questions, risk scoring output details).
- Store risk score outputs in a retrievable format (output format preferences to be confirmed by Luke).
- Allow re-running or applying the algorithm for different environmental condition inputs against existing survey data.

## 3. User Roles & Access

- **End users** must have individual logins and be able to complete surveys and view their own results.
- A **supervisor** role on the client side must be able to view retrieval logs (audit of who accessed data and when) but must **not** be able to view the underlying algorithm.
- Support administrative/system roles for support and maintenance activities (details to be handled in internal planning).

## 4. Security & Compliance

- Host the platform in **Microsoft Azure** and ensure the hosting and architecture address **HIPAA** compliance for handling PHI (specific Azure setup details to be provided by the solution team and agreed with Luke).
- Ensure PHI is protected and that access is auditable as discussed.

## 5. Data Volume & Scalability

- Anticipated initial usage: **12–20 users per site** and **12–30 data entries per week** (per site).
- The system must support these initial volumes and be designed with scalability in mind for future growth.

## 6. User Interface & Development Approach

- Deliver a **simple, test-friendly UI** first to facilitate testing and adjustments by Luke’s team.
- Develop the UI and algorithm backend in parallel, per the discussion.

## 7. Database / Long-Term Storage

- The database design must support building tables that establish relationships between survey answers, environmental conditions, and risk scores (Luke and Zukhruf discussed building out these tables).
- Include consideration for long-term data storage and retrieval/archiving (client raised long-term storage concerns to be addressed).
