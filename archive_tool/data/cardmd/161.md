## Description

Attached is the **RFP for the Oasis Care Navigation Platform** from MuseHealth. Below is a distilled summary of the core requirements and expectations so we can align on approach, architecture, and resourcing before we begin drafting our solution proposal.

---

### **1. Project Vision**

- **Build “Oasis”** – an AI-enabled Care Navigation Platform that integrates modular service lines ("Pods") such as:
  - MSK care
  - Diabetes management
  - Behavioral health
  - Metabolic nutrition
  - Non-emergency medical transport (NEMT)
- **Goals**: Coordinate care, improve outcomes, align incentives via value-based contracts.
- **Target customers**: Employers, payers, community channels.

---

### **2. Technical & Functional Requirements**

**A. Architecture & Interoperability**

- FHIR-first, event-driven architecture with plug-and-play Pod integration.
- Full compliance with **FHIR R4**, **OAuth 2.1**, **OpenID Connect**, **HL7 bulk data**.
- Canonical interoperability layer to handle:
  - Identity via UUIDs
  - Consent hashing (SHA-256)
  - Authentication & transport security (OAuth 2.1, mTLS, JWT)
  - Vocabulary standards: SNOMED CT, LOINC, RxNorm, CPT/HCPCS, UPC/GTIN.
- Eventing & audit:
  - Real-time FHIR Subscriptions
  - Bulk exports via NDJSON/GZIP
  - RFC 9457-compliant error handling.

**B. Coordinated AI Navigation**

- AI-powered decision support that adapts care plans in real time across Pods.
- Context-aware event triggers (e.g., MSK episode triggers diabetes care updates).

**C. Unified API for Clients**

- Single endpoint for employers/payers with:
  - Service utilization data
  - Outcome dashboards
  - ROI/performance reports.

**D. Member & Admin Experience**

- Mobile-first, WCAG 2.0 compliant, multi-lingual (English & Spanish initially).
- ≤2s page load, ≤1s in-app transitions.
- Admin dashboard with role-based access.

**E. Security & Compliance**

- HIPAA, 42 CFR Part 2, CMS Interoperability, NIST 800-53 compliance.
- Zero-trust security model:
  - AES-256 encryption
  - mTLS, IP whitelisting
  - Quarterly penetration tests
  - 15-min token expiry
- See Appendix B in RFP for full control matrix.

---

### **3. Implementation Phases & Timelines**

- **Canonical Mapping Summit** – 3 weeks
- **Reference Sandbox Build** – 4 weeks
- **Pod Certification** – 6 weeks
- **Pilot Thread** – 4 weeks
- **Production Cut-over** – Dec 2025 start (rolling)
- **National Launch** – Sept 2026

---
